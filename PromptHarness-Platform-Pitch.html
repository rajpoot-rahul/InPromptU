Idea title

PromptHarness - one prompt standard for every Hyland AI feature

Problem

Each product team writes and maintains its own prompts. The result:

  • Output formats differ between products.
  • Safety rules are applied unevenly.
  • Teams repeat the same prompt work.
  • When the AI model changes, every team re-tunes separately.

Idea

A "compile" step inside HAIP. A product sends what it wants done plus its content. PromptHarness builds the final prompt from shared, versioned templates.

How it works

  1. Check the request: HS1 identifies the task type (summarise, extract, classify, compare, answer a question) and flags anything missing, such as no output format. Optional and fast.
  2. Build the prompt: a fixed template for that task type fills in role, task, content, limits and output format. Company-wide rules (no personal data in output, cite sources, required format) are added in one place. The same input always gives the same prompt.
  3. Run and check: the model answers, the output is checked against the required format, and any failure is logged against the template version that produced it.

Why it matters to Hyland

  • Rules managed in one place instead of in every product.
  • When the model changes, prompts are re-tuned once, centrally.
  • Teams get good prompts without needing prompt experts.
  • A record of which template produced each answer, which matters for regulated customers.

Demo

  1. Before: two products make the same kind of request; outputs come back in different formats and one misses a safety rule.
  2. After: both go through PromptHarness and return consistent output.
  3. Edit once: change one central template live, and both products improve.

Success signal

On 50 real requests from two product teams, compiled prompts return output in the correct format at least 95% of the time, reviewer-rated quality is no worse than today, and the meaning of the request changes in no more than 2 of the 50 cases.

Risks

  • Teams may not want to give up control: make it opt-in and allow product-specific additions.
  • One template may not fit every use: templates per task type, with extension points for each product.
  • Ownership and overlap: needs a HAIP-team sponsor; HAIP may already offer prompt templates or guardrails.

Before you submit

This is a proposal. The problem and numbers above are assumptions until checked with real teams.
  1. Does HAIP already have prompt templates or guardrails? If yes, pitch this as an extension of what exists.
  2. Is the problem real? Ask two or three product teams how they manage prompts today. One real example of inconsistent output will persuade judges more than anything here.
  3. Are the names right? Confirm the HAIP name and who owns it.
  4. Is the deadline and format known? Adapt the headings to the hackathon's own template if it has one.

Expect the question "Copilot and ChatGPT already improve prompts - why build this?" Answer: this is not about one person's prompt; it is about consistent, governed, versioned AI behaviour across every Hyland product.
