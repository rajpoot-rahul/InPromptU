2. What the idea is, and how it changed

  1. First version, "prompt compiler": an AI rewrites your messy prompt for another AI. Weak: tools like this already exist and the benefit can't be proven.
  2. Platform pitch (PromptHarness-Platform-Pitch.html): one shared prompt standard inside HAIP for all products.
  3. Current version, "task harness": the AI is only one step in a controlled pipeline:
    Pick task → clean document → fixed versioned template → AI → automatic checks → one retry or flag for human review → log
Key message: "Brainware solved document checking for classic capture. As Hyland teams move to generative AI, nothing standard checks the AI's answers. Task Harness is a reusable quality gate for any AI call: it checks, retries, flags, and proves which model is good enough."

Checks the harness runs on every answer: correct format; every value really appears in the document (after normalising formats like 1,20,000.00 or 5 Nov 2026); the value comes from the right line (vendor not "Bill To", invoice date not "Due Date", total not "Amount Due"); the sums add up.

5. How to start the web app

  1. Open the Terminal app.
  2. If it has been a few hours, sign in to AWS again (only needed for Live mode). This opens your browser: 
    aws sso login --sso-session ai-internal-dev
  3. Paste this single line and press Enter: 
    cd /Users/surekha.jaknalli/02_Learning/ideas/promptharness/task-harness && .venv/bin/python -m taskharness serve --aws-profile <your-aws-sso-profile>
  4. Open http://127.0.0.1:8000 in your browser. Keep the Terminal window open. Press Ctrl + C in Terminal to stop.

Optional: run the full comparison again (about 10–15 minutes per model):

cd /Users/surekha.jaknalli/02_Learning/ideas/promptharness/task-harness && .venv/bin/python -m taskharness run --model us.anthropic.claude-haiku-5-5 --aws-profile <your-aws-sso-profile>
Security: never paste API keys or tokens into chat, files or slides. The AWS sign-in above needs no key. If a key is ever exposed, tell your AWS admin or security contact.

6. Demo steps (about 3 minutes)

  1. 1 · Problem (30 s): read the headline, point to the three cards (inconsistent, unchecked, expensive) and the 7-step diagram.
  2. 2 · Try it (60 s): defaults are ready (inv_001 🔁, Full harness, Haiku 5.5). Click Run ▶. Show the steps lighting up, Original vs Cleaned, "🔁 Fixed on retry", the answer table and the checks.
  3. 3 · Side by side (45 s): Haiku plain (left) vs Haiku harness (right) on inv_004 ★. Click Compare ▶. Left: discount wrong, "silent error". Right: correct.
  4. 4 · Results (45 s): read the headline banner; point to "Silent errors" and "Estimated cost" charts.
  5. 5 · Roadmap (30 s): template library, teams add their own, approved models only, audit logs, HS1 as a fast check. Read the "Honest limits" box aloud.

Use Saved run for the main demo: it needs no internet. Live calls Claude in real time and needs a current AWS sign-in.

Test your own file: on 2 · Try it, choose Document → "📄 Your own document (upload or paste)…", upload a .txt file or paste text, and click Run. There is no answer key, so you judge the answer using the checks. Never upload confidential or customer data. If the page says "Not Found", the server is an old copy: stop it (Ctrl + C) and start it again.

7. Likely judge questions

  • "Doesn't Brainware already do invoices?" Yes, for classic capture, and we're not replacing it. Invoices are only our test case because the answers are easy to verify. The gap is generative-AI calls, which usually have no standard checks. The harness is the quality gate for those, and it also proves which model is good enough.
  • "Isn't this just better prompting?" No. The prompt is one step. The value is that code checks every answer and nothing wrong passes silently.
  • "Copilot/ChatGPT already improve prompts. Why build this?" This is not about one person's prompt; it is about consistent, governed, versioned, checked AI behaviour across every Hyland product.
  • "Is the data real?" 30 synthetic invoices with known answers. Next step: real, approved documents from one product team.
